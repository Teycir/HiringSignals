# Hiring Signals Intelligence

## Project Summary
Hiring Signals Intelligence is a web dashboard that surfaces genuine, matching IT job postings as soon as they appear publicly across multiple ATS providers. Built for job seekers who want to see openings before the crowd.

## Tech Stack
- **Frontend**: Next.js 16, TypeScript 5.x, Tailwind CSS
- **Backend**: Cloudflare Workers with Hono framework
- **Database**: Cloudflare D1 (SQLite)
- **Search**: Workers AI (`@cf/baai/bge-base-en-v1.5`) + Vectorize (write path only so far)
- **Package Manager**: pnpm workspace
- **Deployment**: Cloudflare Pages (UI) + Cloudflare Workers (API)

## Architecture
```
apps/web/        Next.js 16 UI -> Cloudflare Pages (still near-scaffold, no dashboard yet)
apps/api/        Cloudflare Worker API: routes, cron scheduler, queue consumer,
                  daily reconciliation job, semantic-search service
packages/domain/ Zod schemas, taxonomies, classification, lifecycle,
                  signal scoring (v2), embedding-text, search-merge
packages/adapters/ AtsAdapter interface; greenhouse + lever implemented, 9 more P0 pending
packages/db/     D1 client + read/write repository functions
packages/ui/     Optional shared UI primitives
infrastructure/  D1 migrations (0001-0004) + ops scripts (add-source, update-source,
                  add-company, source-health, backfill-embeddings)
```

**Done:**

- Hono Worker with full middleware chain, real cron scheduler, real queue consumer, daily reconciliation cron
- 8 P0 ATS adapters implemented with fixture-driven tests & location inference: Greenhouse, Lever, Ashby, Recruitee, Breezy, Personio, SmartRecruiters, Workable (Teamtailor, JazzHR, BambooHR marked as standing wont-builds due to unauthenticated API constraints)
- Full D1 schema with indexes, migrations 0001-0004
- Parameterized D1 client wrapper with read (signals/companies/facets/export) and write (sources/jobs/signals/companies) repositories
- API routes querying D1 for real: GET /api/v1/signals, /signals/:id, /companies, /companies/:slug, /facets, /sources, /export/signals.csv

- Domain lifecycle refinement: 3-day absence threshold (`daysSinceLastSeen >= 3`) before flagging reopened roles
- Jobs embedded into a Vectorize index at ingest time (semantic search write path); query-side hybrid search service & merge logic implemented
- Zero-mocks live test infrastructure (`packages/test-support`) against real Cloudflare D1/KV resources
- All workspace tests passing workspace-wide (`pnpm -r test`); `pnpm -r typecheck`/`pnpm -r lint` clean

**Not yet done:**

## Key Features
- **Role-level signals**: New matching roles, reopened roles, still active roles
- **Company-level signals**: Hiring bursts, demand acceleration, multi-location expansion, persistent demand
- **Evidence trails**: Source platform, canonical public URL, source job identifier, timestamps
- **Filtering**: By role, location mode, country, source, signal type, score, and company; keyword search on company/headline/summary
- **Export**: CSV export of filtered signal list (spec §10.6, not yet built)
- **Scheduled ingestion**: Cloudflare Worker cron triggers (15-min source scheduler, daily reconciliation) with adaptive cadence per provider

## Non-goals for v1
- No collection of private profiles or personal data
- No bypassing logins, CAPTCHAs, rate limits, robots directives
- No general-purpose HTML scraping (official ATS APIs only)
- No push notifications, email digests, or webhook alerting
- No automated sending of cold email or LinkedIn messages
- No claims about confirmed projects, budgets, or purchasing decisions
