# Hiring Signals Intelligence

## Project Summary
Hiring Signals Intelligence is a CLI-first tool, built for AI agents to query on a person's behalf, that surfaces genuine, matching IT job postings as scored, filterable signals as soon as they appear publicly across 8 ATS providers via official documented APIs (no scraping). Signals go beyond raw job listings to detect what is actually happening: new roles, reopened roles, hiring bursts, role acceleration, multi-location expansion, persistent demand. Designed for job seekers who want to see openings before the crowd, analysts/investors tracking hiring velocity, and AI agents acting on a person's behalf.

## Tech Stack
- **Interface**: Two front doors over the same `apps/api` — `apps/cli` (complete, landed 2026-08-07), a thin JSON-by-default CLI client (`--format table` for interactive human use, added 2026-08-10, no interactive prompts), primary interface for AI agents; and `apps/web`, a Next.js 16 dashboard, deleted 2026-08-07 in the original CLI-first decision, then **restored 2026-08-16** (commit `1bc7a97`) once it was clear the dashboard added real value for human users browsing rather than querying. Both stayed live and current through the 2026-08-17 S/T/U/V/W hardening passes.
- **Backend**: Cloudflare Workers with Hono framework
- **Database**: Cloudflare D1 (SQLite), 10 migrations (0001-0010)
- **Search**: Workers AI (`@cf/baai/bge-base-en-v1.5` embeddings) + Vectorize — hybrid semantic search: embeddings generated at ingest time (I.2), query-side merge with keyword results wired live into GET /api/v1/signals (I.3), falls back to keyword-only on subsequent pages or if the AI leg is unavailable
- **Package Manager**: pnpm workspace
- **Deployment**: Two Cloudflare Workers, same account: `hiring-signals-api` (backend, includes the 2026-08-17 S/T/U/W fixes; last confirmed version in this file is `6f82cd4a` from 2026-08-14 — deployed again since but no newer version string has been recorded here yet) and `hiring-signals-web` (`apps/web`, restored 2026-08-16, deployed via `@opennextjs/cloudflare`, Worker version `56084565` as of 2026-08-17). The two talk to each other over a Cloudflare service binding, not the public internet (fixed as W.4 — see below).
- **Validation**: Zod schemas — as of the 2026-08-17 api-client consolidation, `apps/web`'s param types derive from the same schemas `apps/cli` and the live routes validate against, via a new shared `packages/domain/src/api-client-core.ts`.
- **Code Quality**: ESLint 10 flat config (--max-warnings 0), Prettier, strict TypeScript with noUncheckedIndexedAccess

## Key Features
- **Role-level signals**: New matching roles, reopened roles (3-day absence threshold), still active roles (daily reconciliation appends still_active evidence to prevent score decay)
- **Company-level signals**: Hiring bursts (3+ same-role postings in 14d), role acceleration (pace vs 56d baseline), multi-location expansion (3+ distinct locations same role), persistent demand (30+ days continuously active)
- **Hiring velocity per company**: 0-100 investor-grade score = 0.40*acceleration + 0.25*breadth + 0.20*volume_norm + 0.15*persistence; recomputed daily only for touched companies; null means not-yet-computed (never fabricated as 0); shared HIRING_VELOCITY_DISCLAIMER on every response carrying it
- **Evidence trails**: Source platform, canonical public URL, source job identifier, timestamps, title, location, department
- **Hybrid search**: Keyword + semantic (Workers AI embeddings + Vectorize cosine) merged on page 1 of signals; falls back to keyword-only gracefully if semantic path degrades
- **Filtering**: By role (10 IT categories, comma-delimited), location mode, country, source, signal type, min score, company, recency window, free-text company/headline/summary keyword search
- **Saved filter profiles (CLI-local only)**: `hs signals list --save` persists raw pre-parse flags at `~/.hiring-signals/config.json`; auto-applied with a one-line stderr note on no-flag runs
- **Cross-company hiring trends**: `GET /trends/hiring` + `hs trends hiring` ranked company analytics with acceleration_desc/volume_desc/newest_signal/velocity_desc sorts, industry/country/role/recency filters, per-company top-5-location breakdowns, KV-cached 5 minutes
- **Single-company hiring timelines**: `GET /companies/:slug/timeline` + `hs companies timeline` time-bucketed new/closed/active jobs per 7/14/30-day window (90-day cap) with role/location breakdowns and signal types per bucket
- **Push-style delivery via RSS**: `GET /feed.rss` + `hs feed-url` for feed-reader subscriptions, no accounts, no personal data. 50-item cap, ETag/Last-Modified/304 Not Modified conditional-request support, filterable by all the same signal filters
- **Export**: CSV export of filtered signal list via `GET /api/v1/export/signals.csv` (same filters, 2000-row cap with truncation header; also `hs export signals`)
- **Bulk onboarding**: CSV import (import-sources.mjs) for batch source/company creation with pre-validation and duplicate skipping
- **Scheduled ingestion**: Cloudflare Worker cron triggers (15-min source scheduler with deterministic per-source jitter, daily reconciliation at 06:00 UTC) with per-provider adaptive cadence; hasRecentRunningRun(45min) guard prevents scheduler stacking of abandoned runs
- **Multi-chunk board processing**: Boards >40 jobs split into sequential chunk invocations via continuation queue messages to stay under Cloudflare's 1000-service-subrequest-per-invocation free-plan cap; total ~14 worst-case subrequests per new job
- **Monitoring & observability**: source-health.mjs (stale/stuck/degraded detection with 90min stuck threshold), ingestion-metrics.mjs (success rate + duplicate rate with/without requisitionId tiering), and per-request Analytics Engine data points for API error rates/latency histograms with normalized route-shape cardinality

## Non-goals for v1
- No collection of private profiles or personal data
- No bypassing logins, CAPTCHAs, rate limits, robots directives
- No general-purpose HTML scraping (official ATS APIs only)
- No email digests, webhook alerting, or browser push notifications (RSS feed route via external feed reader handles "notify me later" — feed is still pull-from-the-reader's-perspective, not a direct outbound push from this app)
- No automated sending of cold email or LinkedIn messages
- No claims about confirmed projects, budgets, or purchasing decisions; company-level hiring claims use the shared HIRING_VELOCITY_DISCLAIMER
